# Games Art & Design Academic Research System

一个面向游戏艺术、游戏设计与技术研究的文献逆向拆解仓库。

本仓库不以“收藏文献”为目标，而是把每篇材料转化为五类可复用成果：

1. **学术家谱**：研究问题如何演化，前人解决了什么瓶颈。
2. **高阶语料**：可学习的论证结构、转折方式与因果表达。
3. **核心逻辑**：论文主张如何落到方法、代码或设计实践。
4. **实现鸿沟**：理论描述与实际实现之间的缺口。
5. **研究机会**：能够验证、复现或发展成项目的问题。

> 当前版本只包含框架和模板，尚未录入任何文献。

## Repository Map

| 目录 | 作用 | 主要产出 |
|---|---|---|
| `00-dashboard/` | 管理研究问题、阅读队列和进度 | 研究仪表盘 |
| `01-lineage/` | 追踪近年研究演化与瓶颈 | 时间轴、方法谱系 |
| `02-narrative/` | 积累学术论证与表达结构 | 语料库 |
| `03-core-logic/` | 拆解方法、实验、代码和设计逻辑 | 核心逻辑卡 |
| `04-synthesis/` | 跨文献比较并形成研究空白 | 研究机会清单 |
| `templates/` | 为每次拆解提供统一格式 | 可复制模板 |

## Three-Pass Workflow

### Pass 1 — Trace the Lineage

先识别研究问题、前置工作、方法变化和未解决瓶颈。此阶段不逐字翻译，也不急着处理公式。

### Pass 2 — Extract the Narrative

提取论证结构，而不是机械收藏“高级词汇”。记录表达承担的功能、适用语境和可迁移句型。

### Pass 3 — Run the Core Logic

把论文主张转写为输入、处理、输出、假设和验证方式。存在代码时记录最小复现路径；没有代码时转化为可执行的设计或实验流程。

完成三轮后，将发现汇总到 `04-synthesis/`，判断它属于证据缺口、方法缺口、实现缺口还是应用缺口。

## Working Rules

- 一篇文献对应一张拆解卡，文件名使用 `YYYY-author-short-title.md`。
- 事实、作者观点和个人推断必须分开记录。
- 摘录只保存必要短句，并标注页码或位置。
- 无法验证的判断标记为 `待验证`。
- “研究空白”必须能转化为一个可测试的问题。
- 代码复现应链接到独立实验目录或原始仓库，不把大型生成文件提交到本仓库。

## Start Here

1. 在 `00-dashboard/README.md` 写下一个明确研究问题。
2. 复制 `templates/paper-breakdown.md` 创建第一张拆解卡。
3. 完成三轮拆解。
4. 把跨文献结论写入 `04-synthesis/README.md`。
